## 一、名词速懂（5 秒）

- **APNs**：苹果的推送通道，所有 iPhone 推送的最后一公里，必走。
- **FCM**（Firebase Cloud Messaging）：谷歌推送服务。安卓走它；它能代转到 APNs，所以一套接口推 iOS+安卓。
- **Firebase**：谷歌的 App 平台，FCM 是其中的「推送」模块。配推送＝在 Firebase 控制台建项目。

链路：`后端(有事件) → FCM → 安卓手机 / 经 APNs → iPhone`

## 二、要准备的东西（按角色）

### 角色 A：项目持有人 / @Elon —— 建 Firebase 项目 + 拿配置文件
1. 打开 https://console.firebase.google.com ，用**要长期持有 DINQ 项目的 Google 账号**登录。
2. **Add project / 添加项目** → 项目名 `DINQ Mobile` → 一路下一步（**会让你接受服务条款，必须勾**）→ 创建。
   - ⚠️ 新账号第一次用 Firebase 必须在这一步接受条款，否则命令行建项目会报 `403 PERMISSION_DENIED`。
3. 进项目 → **添加 Android 应用**：
   - Android 包名填 `me.dinq.app`
   - 下载 **`google-services.json`** → 交给前端（替换 `android/app/google-services.json` 占位文件）
4. 进项目 → **添加 iOS 应用**：
   - iOS Bundle ID 填 `me.dinq.app`
   - 下载 **`GoogleService-Info.plist`** → 交给前端（放进 `ios/Runner/`）
5. 记下**项目 ID**（形如 `dinq-mobile-xxxxx`）发前端。

> 也可让前端用 `flutterfire configure --project=<项目id>` 一键生成上面两个文件，但**前提是第 2 步的条款已在控制台接受过**。

### 角色 B：iOS 同学 —— APNs 证书（iOS 推送必须）
> 没有这一步，**安卓能推、iPhone 不能推**。

1. 打开 https://developer.apple.com/account/resources/authkeys/list （DINQ 的 Apple 开发者账号）
2. 创建一个 **APNs Auth Key**（Keys → +，勾选 Apple Push Notifications service (APNs)）→ 下载 `.p8` 文件，记下 **Key ID** 和 **Team ID**。
3. 回 Firebase 控制台 → 项目设置 → Cloud Messaging → Apple app configuration → **上传 APNs Auth Key**（传 `.p8` + 填 Key ID + Team ID）。
   - 文档：https://firebase.google.com/docs/cloud-messaging/ios/certs
4. Xcode 打开 `ios/Runner.xcworkspace` → Runner target → Signing & Capabilities → 添加：
   - **Push Notifications**
   - **Background Modes** → 勾 **Remote notifications**
   - （`Info.plist` 的 `UIBackgroundModes` 已预置，无需手动加）

### 角色 C：后端 fyr —— 确认两件事
1. **`/devices` 接口已建好**（已实测，无需再动）：
   - `POST /api/v1/devices` body `{ "token": "...", "platform": "ios"|"android" }` → 200，返回 `device{id,user_id,token,platform,enabled,...}`
   - `DELETE /api/v1/devices/{token}` → 200 device unregistered
   - 客户端契约与此**完全一致**。
2. **发推送服务**（待确认）：业务事件发生时（新私信 / Radar 新候选人 / 系统通知），后端是否已**读 devices 表里的 token 调 FCM/APNs 发送**？
   - 若未接，按 https://firebase.google.com/docs/cloud-messaging/send-message （Admin SDK 或 HTTP v1）实现。
   - **推送 payload 约定**（客户端点击跳转依赖）：`data` 带 `type` + 对应 id：
     - `type=message` / `team_recruit` + `conversation_id` → 跳会话
     - `type=radar` + `candidate_id` → 跳候选人/通知中心
     - `type=system` + `notification_id` → 跳通知中心

## 三、文件落点对照（前端接收后放哪）

| 文件 | 谁给 | 放到 | 备注 |
|---|---|---|---|
| `google-services.json` | 角色 A | `android/app/google-services.json` | 替换现有占位文件 |
| `GoogleService-Info.plist` | 角色 A | `ios/Runner/`（加入 Xcode 工程） | iOS Firebase 连接 |
| `.p8` APNs Key | 角色 B | 上传到 Firebase 控制台（不进代码库） | iOS 推送通行证 |

> ⚠️ 注意区分：之前群里发过的 `client_xxx.apps.googleusercontent.com.plist` 是 **Google 登录(OAuth)** 用的，**不是推送文件**，且已接入，无需再放。
> 推送文件认准字段：`GoogleService-Info.plist` / `google-services.json` 里有 **`GCM_SENDER_ID` / `PROJECT_ID`**；OAuth 那个只有 `CLIENT_ID`。

## 四、验证（配完怎么测）

1. 前端 `flutter pub get` → `flutter run --release` 装到**真机**（模拟器收不到推送）。
2. 登录测试账号 → 控制台/日志确认设备 token 上报成功（`POST /devices` 返回 200，无 `[PushService] ... failed`）。
3. Firebase 控制台 → Cloud Messaging → **发送测试通知**，验证：
   - 前台：App 内弹本地通知
   - 后台/杀掉：系统通知栏弹出
   - 点击通知：跳到对应页（私信→会话 / 系统→通知中心）
4. 后端联调：真实发一条私信 → 对方真机收到系统推送。

## 五、联调顺序建议

1. **角色 A 建 Firebase 项目 + 给两个配置文件** → 前端接入 → 安卓真机先跑通（安卓不依赖 APNs）。
2. **角色 B 配 APNs** → iOS 真机跑通。
3. **角色 C 确认发推送服务** → 业务事件触发的真实推送跑通。
